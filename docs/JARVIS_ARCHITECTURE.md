# Мониторинг Telegram-ассистента на Claude Code

Как Magic Hub следит за «Джарвисом» — личным ассистентом в Telegram, который работает как Claude Code CLI в режиме каналов. Подходит для любого такого бота: пути и служба находятся автоматически или задаются в настройках (раздел «ИИ-агенты и Джарвис»). Если бота нет, вкладка честно показывает «Не найден».

## Как устроен такой бот

```
claude --channels plugin:telegram@claude-plugins-official [--continue]
```

- Сообщения из Telegram приходят в сессию через плагин `telegram` (MCP-сервер на Bun), ответы уходят инструментом `reply`.
- Бота запускает служба `launchd` из `~/Library/LaunchAgents/` с `KeepAlive`, поэтому после падения он перезапускается сам.
- История сессии пишется Claude Code в `~/.claude/projects/<путь к папке бота, где «/» и «.» заменены на «-»>/*.jsonl`.
- Скрипты и логи бота лежат в отдельной папке (по умолчанию `~/.jarvis`: `bin/restart`, `logs/bot.log`).

## Что измеряет Magic Hub

| Показатель | Откуда | Норма / тревога |
|---|---|---|
| Сессия жива | процесс `claude --channels` (без обёрток `zsh`/`script`/`caffeinate`) | нет процесса больше минуты — тревога |
| Telegram подключён | процесс bun c `…/telegram/` | 0 — бот не получает сообщения; больше 1 — два поллера, сообщения теряются |
| Занят / свободен | конец последнего `*.jsonl`: запись `"subtype":"turn_duration"` значит «ход закончен» | — |
| Завис | занят, а файл сессии не менялся больше 10 минут | показать и предложить перезапуск |
| Первый ответ | от сообщения `<channel …>` до первого вызова `…reply` | больше 2–3 минут — плохо |
| Контекст | у последнего ответа модели: `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` | больше 100 тыс. — скоро сжатие, больше 150 тыс. — тормозит |
| Ошибки и лимиты | записи с `isApiErrorMessage: true` или `error` (`rate_limit` — кончился лимит подписки) | любая — показать |
| Сжатия контекста | `type=system`, `subtype` содержит `compact` | частые — признак раздувания |
| Длительность ходов | `type=system`, `subtype=turn_duration`, `durationMs` | медиана больше 60 с — медленно |
| Перезапуски | строки «запуск…» в логе бота за сегодня | частые короткие — бот падает |
| Сеть (по кнопке) | задержка до `api.telegram.org`, отдача на `speed.cloudflare.com` | отдача меньше 1 Мбит/с — всё будет медленно |

## Управление из Magic Hub

- **Мягкий перезапуск** — скрипт `<папка скриптов>/bin/restart "…"`, если он есть: бот перезапускается и сам продолжает задачу.
- **Жёсткий перезапуск** — `launchctl kickstart -k gui/<uid>/<служба>`; если бот занят, Magic Hub переспросит.
- **Остановить / запустить** — `launchctl bootout` / `launchctl bootstrap`.

## Правила

- Не запускать второй экземпляр бота и не включать плагин `telegram` в других сессиях: два поллера с одним токеном перехватывают сообщения друг у друга.
- Не перезапускать посреди хода без подтверждения: оборвётся задача.
- Ничего не хардкодить: пути, служба, имя пользователя — автоопределение или настройки.
- Никогда не коммитить токены, `.env`, `access.json`, память бота, JSONL-сессии и логи — там личная переписка (см. `.gitignore`). Magic Hub читает их только локально и никуда не отправляет.
